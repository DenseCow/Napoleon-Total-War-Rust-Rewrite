**Why the data crosses as arrays and not as a type.** `ntw_sim` and `ntw_formats` are both

putting `ntw_formats` under `ntw_sim` would put file I/O inside the audited model crate. So the
solve's input is [`ClothParts`], a **tuple of standard-library types**, spelled identically on both
sides; the only conversion is the field copy in `ClothSpec::parts`, and the link order (the solve is
Gauss-Seidel, so order is part of the result) survives it. `ntw_sim` carries its own
`transform_point` for the same reason; the install test asserts it equals
`ntw_formats::anim::transform_point` on all 42 shipped particles of the shipped bone.
