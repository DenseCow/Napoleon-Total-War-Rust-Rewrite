# S3 debugger probe: which soldiers fire (2026-10-04, live original game)

**Setup.** Microsoft WinDbg (`cdb.exe`, x86) attached to the vanilla original `Napoleon.exe` 1.3.0.0 (timestamp 0x645e917f)
while the user played a battle with infantry firing. Script: `fire_probe.cdb.txt` (breakpoints that log the call chain and
continue; detaches itself after 400 FIRE hits). Load base this run: 0x00E50000 (ASLR); static VA = runtime − 0xE50000 + 0x400000.

**Breakpoints.** FIRE enter `0x00805B80` (musket FSM, vtable 0x01348738), the fire-behaviour giver `0x005DFA90`, the
engagement builder `0x00662E90`.

**Results (CONFIRMED, runtime).**
- FIRE enter: 585 hits, **488 distinct soldier objects** (ecx) during the volleys. Every chain that unwinds (38) is
  `0x00805B80 ← 0x007DEDC2 ← 0x010FBBF6 ← 0x00818CDC ← 0x00658F84 ← (0x00819CB8 | 0x0066BB97 → 0x007FD052 | 0x00FF7FBF)`;
  `0x00658F84` is in the soldier update (next to the speed update `0x006543D0` / `0x006544E0`). The other 547 hits did not
  unwind (frame-pointer-less frames), not a different caller.
- Fire-behaviour giver `0x005DFA90`: **0 hits** with infantry firing → the infantry fire path does NOT go through it
  (it is the mounted/crew path, as round 15 found).
- Engagement builder `0x00662E90`: 336 hits, all melee chains (`← 0x00672B31 ← 0x0066E753 / 0x006666D4 …`).

men fire. If needed, a second probe can log that function's arguments and the soldier's unit/rank (script template here).
